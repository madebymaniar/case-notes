## ✦ What are Case Notes?

Not every interesting problem needs a finished product.

Sometimes the most valuable thing is simply noticing something others have learned to ignore.

**Case Notes** is where I document those moments.

A broken experience.  
An unnecessary step.  
A strange workflow.  
A missed opportunity.  
A system that works — but could work much better.

Each note starts with an observation and follows the question:

> **“What could this become if we looked at it differently?”**

---

## ✦ The Structure

Every Case Note follows the same path:

**01 — The Observation**  
What caught my attention?

**02 — The Friction**  
Where does the problem actually hurt?

**03 — The Question**  
What assumption is worth challenging?

**04 — The Idea**  
What could a better version look like?

**05 — How It Could Work**  
How might the idea behave in the real world?

**06 — The Impact**  
What could actually improve?

**07 — What I'd Test First**  
What's the smallest experiment worth trying?
